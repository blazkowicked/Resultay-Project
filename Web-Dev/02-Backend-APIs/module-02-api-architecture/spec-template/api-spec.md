# API Specification — Portfolio Projects API

This document specifies the REST API for managing the **projects** displayed in a personal portfolio website. The API is backed by a Supabase project (managed PostgreSQL exposed through PostgREST). It reads as a contract: if you follow the requests below, you will get the responses documented here. No prior knowledge of the codebase is required.

---

## 1. Base URL

```
https://iwsfzylwsxuovnkapylo.supabase.co/rest/v1/
```

Every request in this document is relative to this base URL.

### Authentication Headers

All requests must send at least the `apikey` header (the **anon key** from Supabase *Settings → API*). Requests that create, update, or delete data must also send a user JSON Web Token (JWT) obtained from Supabase Auth.

| Header | Required | Value |
|--------|----------|-------|
| `apikey` | Yes | `<project anon key>` |
| `Authorization` | Only for write operations | `Bearer <user JWT>` |
| `Content-Type` | Yes (for requests with a body) | `application/json` |
| `Accept` | Yes | `application/json` |

> **Security note:** the anon key is safe to expose in client code. The **service role key** must never be sent from the client; it bypasses Row Level Security and is reserved for server-side/admin operations.

## 2. Response Format

Every response uses a consistent JSON envelope.

**Success:**
```json
{
  "status": "success",
  "data": { }
}
```

**List endpoints** add a pagination object:
```json
{
  "status": "success",
  "data": [ ],
  "pagination": { "page": 1, "limit": 10, "total": 25 }
}
```

**Error:**
```json
{
  "status": "error",
  "message": "Project not found",
  "code": "NOT_FOUND"
}
```

| Envelope field | Type | Meaning |
|----------------|------|---------|
| `status` | string | `"success"` or `"error"` |
| `data` | object/array | The resource or list of resources (`null` on errors) |
| `pagination` | object | Only on list endpoints: current `page`, `limit`, and total `total` count |
| `message` | string | Human-readable error description (errors only) |
| `code` | string | Machine-readable error code (errors only) |

## 3. Data Model

### Table: `projects`

| Column | Type | Notes |
|--------|------|-------|
| `id` | `uuid` | Primary key, generated by the server |
| `title` | `text` | Required, 1–100 characters |
| `description` | `text` | Optional, max 500 characters |
| `technologies` | `text[]` | Optional, max 10 items |
| `github_url` | `text` | Optional, valid `https` URL |
| `live_url` | `text` | Optional, valid `https` URL |
| `created_at` | `timestamptz` | Set by the server |
| `user_id` | `uuid` | Foreign key to `auth.users`; set by the server from the JWT |

Row Level Security (RLS) is enabled:
- **Public read:** anyone can read projects (`SELECT` allowed).
- **Write scoped to owner:** a user can only create, update, or delete their own rows (`user_id` must equal `auth.uid()`).

**Example project object:**
```json
{
  "id": "a1b2c3d4-e5f6-4759-8aba-1234567890ab",
  "title": "Weather Dashboard",
  "description": "Live weather map for cities worldwide.",
  "technologies": ["React", "Supabase", "OpenWeather API"],
  "github_url": "https://github.com/me/weather-dashboard",
  "live_url": "https://weather-dashboard.vercel.app",
  "created_at": "2026-09-01T12:00:00.000Z",
  "user_id": "f0e1d2c3-b4a5-4927-8fef-9a8b7c6d5e4f"
}
```

## 4. Endpoints

### 4.1 GET /projects

Retrieve all projects, newest first. Results are paginated and can be filtered.

| Property | Value |
|----------|-------|
| Method | `GET` |
| Path | `/projects` |
| Auth required | No (anon key only) |

**Query parameters:**

| Parameter | Type | Default | Rules |
|-----------|------|---------|-------|
| `page` | integer | `1` | Min 1 |
| `limit` | integer | `10` | Min 1, max 100 |
| `title` | string | — | Optional, partial case-insensitive match on `title` |

**Example request:**
```
GET /projects?page=1&limit=10
```

**Example response — `200 OK`:**
```json
{
  "status": "success",
  "data": [
    {
      "id": "a1b2c3d4-e5f6-4759-8aba-1234567890ab",
      "title": "Weather Dashboard",
      "description": "Live weather map for cities worldwide.",
      "technologies": ["React", "Supabase", "OpenWeather API"],
      "github_url": "https://github.com/me/weather-dashboard",
      "live_url": "https://weather-dashboard.vercel.app",
      "created_at": "2026-09-01T12:00:00.000Z",
      "user_id": "f0e1d2c3-b4a5-4927-8fef-9a8b7c6d5e4f"
    }
  ],
  "pagination": { "page": 1, "limit": 10, "total": 25 }
}
```

**Status codes:**

| Code | When returned |
|------|---------------|
| `200 OK` | Request succeeded; returns zero or more projects |
| `401 Unauthorized` | `apikey` header missing or invalid |
| `429 Too Many Requests` | Rate limit exceeded |
| `500 Internal Server Error` | Unexpected server failure |

## 5. Request Validation Rules

> **Stretch goal.** These rules are enforced by the API before any write reaches the database.

### 5.1 Common rules (all bodies)

- Body must be valid JSON; otherwise `400` with `code: "INVALID_JSON"`.
- Unknown fields are rejected; otherwise `400` with `code: "UNKNOWN_FIELD"`.
- Strings are trimmed before validation.

### 5.2 POST /projects — full resource required

| Field | Type | Required | Rules |
|-------|------|----------|-------|
| `title` | string | Yes | Trimmed; min 1, max 100 characters |
| `description` | string | No | Max 500 characters; `null` allowed |
| `technologies` | array of strings | No | Min 0, max 10 items; each item 1–30 characters; all strings |
| `github_url` | string | No | Must parse as valid `https` URL; max 2048 characters |
| `live_url` | string | No | Must parse as valid `https` URL; max 2048 characters |

If any rule fails, the response is `400` with `code: "VALIDATION_ERROR"` and a `message` naming the offending field.

### 5.3 PATCH /projects/:id — partial update allowed

- The same field rules as §5.2 apply.
- `title` may be omitted, but if present must satisfy the same rules as `POST`.
- An empty body `{}` returns `400` with `code: "EMPTY_UPDATE"`.

## 6. Status Code Reference

| Code | Name | Endpoints | When returned |
|------|------|-----------|---------------|
| `200` | OK | `GET /projects`, `GET /projects/:id`, `PATCH /projects/:id` | Successful read or update |
| `201` | Created | `POST /projects` | Project successfully created |
| `204` | No Content | `DELETE /projects/:id` | Project successfully deleted |
| `400` | Bad Request | `POST /projects`, `PATCH /projects/:id` | Invalid JSON or validation failure |
| `401` | Unauthorized | All | Missing/invalid `apikey` or `Authorization` header |
| `403` | Forbidden | `GET/PATCH/DELETE /projects/:id`, `POST /projects` | Authenticated but RLS denies (e.g., not the owner) |
| `404` | Not Found | `GET/PATCH/DELETE /projects/:id` | No project matches the given `id` |
| `429` | Too Many Requests | All | Rate limit exceeded (see §7) |
| `500` | Internal Server Error | All | Unexpected server-side failure |

## 7. Rate Limiting

> **Stretch goal.** Design documentation for protecting the public API from excessive traffic.

### 7.1 Strategy

Two-tier rate limiting:

1. **IP-based token bucket** at the API gateway / edge (applies to unauthenticated reads).
2. **User-based token bucket** keyed on the JWT subject (`auth.uid()`) for authenticated writes.

A token bucket is refilled at a fixed rate (e.g., 1 token per second = 60/minute); each request consumes one token. When the bucket is empty the request is rejected.

### 7.2 Limits

| Endpoint | Scope | Limit |
|----------|-------|-------|
| `GET /projects` | Per IP address | 60 requests / minute |
| `GET /projects/:id` | Per IP address | 60 requests / minute |
| `POST /projects` | Per user | 10 requests / minute |
| `PATCH /projects/:id` | Per user | 30 requests / minute |
| `DELETE /projects/:id` | Per user | 5 requests / minute |

### 7.3 Response headers (every response)

| Header | Meaning |
|--------|---------|
| `RateLimit-Limit` | Requests allowed per window |
| `RateLimit-Remaining` | Requests left in the window |
| `RateLimit-Reset` | Unix timestamp when the window resets |

### 7.4 When the limit is exceeded

```
429 Too Many Requests
Retry-After: 60
```
```json
{
  "status": "error",
  "message": "Rate limit exceeded, retry after 60 seconds",
  "code": "RATE_LIMITED"
}
```

### 7.5 Supabase notes

Supabase plans ship with built-in API rate limits (credit-based) for `/rest/v1`. For custom limits as designed above, configure them on the Supabase project (Dashboard → Project Settings → API) and/or enforce stricter per-route limits in an auth-aware backend or edge function that fronts the anon-key REST endpoint. Custom limits here are part of the application design, not a Supabase guarantee.
